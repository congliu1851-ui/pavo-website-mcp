# 调用示例

以下都是参数示例，不会自行执行。先读取实时ID、模型、风格和模板，用真实值替换占位文字；不要直接提交这些占位内容。费用授权应明确模型、参数、数量和本次范围。

## 剧情文本交给AI分集

调用`pavo_script_import_text`：

```json
{
  "raw_text": "一位守雪人捡到失踪的雪铃，循着铃声寻找春天。此处替换为完整剧情。",
  "title": "雪铃",
  "planned_episode_count": 6,
  "ratio": "9:16",
  "style": {"style_id": "实时风格ID"},
  "operation_id": "雪铃-AI分集-001"
}
```

计划集数由用户指定，Pavo负责分集安排。style也可用`{"custom_style_prompt":"明确的自定义视觉风格"}`，两种风格方式只选一种。标题是生成参考，不保证成为官网项目名。

## 文件交给AI分集

先调用`pavo_script_upload_file`，参数为`{"path":"/ABSOLUTE/PATH/剧情.docx","operation_id":"剧情上传-001"}`。该步骤会上传并检查文件，但不创建剧本项目。

然后调用`pavo_script_import_file`：

```json
{
  "upload_operation_id": "剧情上传-001",
  "planned_episode_count": 6,
  "ratio": "9:16",
  "style": {"style_id": "实时风格ID"},
  "operation_id": "剧情-AI分集-001"
}
```

本地原文件必须仍存在且SHA相同。该工具使用已上传回执核来源，再把剧情文本发给AI生成接口；不重新上传、不读取任意远端文件。生成后查project_id的进度，待确认时先看大纲，再单独确认。不要同一内容创建多个操作号碰运气。

## 批量搭图

调用`pavo_apply_canvas`，先dry_run=true：

```json
{
  "project_uuid": "真实项目UUID",
  "canvas_uuid": "真实画布UUID",
  "operation_id": "第01镜-搭图-001",
  "dry_run": true,
  "operations": [
    {"op":"create","as":"说明","type":"text","prompt":"雪庭中少女抬头追雪"},
    {"op":"create","as":"生成","type":"video","model":"实时可用模型code","prompt":"镜头缓推，保留人物和服装"},
    {"op":"connect","source":"$说明","target":"$生成","role":"prompt","media_order":0}
  ]
}
```

核计划后，同一参数和同一操作号改dry_run=false应用；再调用validate_canvas。预览不锁定之后的网页修改，提交前仍会重新核验。

## 首尾帧与多图参考

先读取实时tool-specs。guide的extra.node_list中，action_type=input的node_key才是真实输入键。调用`pavo_apply_template`：

```json
{
  "project_uuid": "真实项目UUID",
  "canvas_uuid": "真实画布UUID",
  "code": "实时guide code",
  "inputs": {"实时首帧键":"已有首帧节点key","实时尾帧键":"已有尾帧节点key"},
  "model": "账号实时可用模型code",
  "prompt": "保持人物身份和服装，自然过渡，镜头小幅缓推",
  "operation_id": "第01镜-首尾模板-001",
  "dry_run": true
}
```

普通多图、视频、音频参考用connect_references按media_order连接。是否支持这些素材类型取决于所选模型，音频参考不等于精确台词或口型同步。模板输入也不保证首尾像素完全硬锁。

## 手动新增资料与状态

新增角色调用`pavo_script_create_asset`，传project_id、asset_type=character、name、description、state_name及operation_id；scene/prop分别是场景/道具。

编辑前先get_assets。改实体名用对应asset指纹；编辑状态用对应states指纹。新增状态示例：

```json
{
  "project_id": "真实剧本项目ID",
  "asset_type": "scene",
  "asset_id": "真实场景ID",
  "patch": {"state_name":"夜景","description":"月光下的庭院，薄雪覆盖石阶。"},
  "operation_id": "庭院-新增夜景-001"
}
```

新增状态不传state_id/expected_sha256。保存只维护资料，核对完需要同步时再明确调用finalize_assets。

## 上传图片设为资产形象主图

先用`pavo_upload_media`上传图片；如需账号素材库记录，再创建upload节点并调用`pavo_save_node_asset`。随后get_assets取得目标状态及最新指纹，调用`pavo_script_set_asset_main_image`：

```json
{
  "project_id": "真实剧本项目ID",
  "asset_type": "character",
  "asset_id": "真实角色ID",
  "state_id": "真实状态ID",
  "image_url": "https://已上传图片的公网地址/portrait.png",
  "width": 1086,
  "height": 1448,
  "expected_sha256": "get_assets返回的对应状态指纹",
  "operation_id": "角色-基础形象主图-001"
}
```

scene和prop同样适用。填写实际图片宽高；工具计算比例并回读`main_image`核验，不需改描述或追加reference_images。成功后可再次get_assets确认；UNKNOWN先核操作回执与官网，禁止重新上传绑定碰运气。

角色的四视图需另外上传，并单独调用`pavo_script_set_character_four_view_image`。参数与主图类似，但省略`asset_type`；使用四视图的URL、实际横向宽高和刚回读的状态指纹，另给稳定操作号。该工具更新`three_view_image`并核对原`main_image`保留，不能用参考图字段代替。

## 编辑已有分镜并保留媒体

每次只编辑同一个片段，整集按片段依次保存。先读取`pavo_script_get_storyboard(project_id, episode_id)`，保存原分镜及`_mcp_fingerprints.storyboard`。再调用以下工具；示例中的项目、分集、镜头及指纹都须换成刚回读的真实值。

```json
{
  "tool": "pavo_script_update_storyboard",
  "arguments": {
    "project_id": "真实项目ID",
    "episode_id": "真实分集ID",
    "shots": [{
      "shot_id": "真实镜头ID",
      "content_rich": "近景，平视。人物的目光从桌面移向对手，吸气后压低声音回答，句尾放缓。原台词逐字保留，表演说明写在台词外。",
      "duration_sec": 6
    }],
    "scenes": [],
    "expected_sha256": "刚回读的_mcp_fingerprints.storyboard",
    "operation_id": "该次实际修改的稳定操作号"
  }
}
```

`content_rich`中的人物、场景和道具使用本项目真实素材标签；工具允许明确替换引用，并核对派生素材引用、视频提示词和段总时长。它不改资产本体、不重新生成或清除已有媒体。回读不符或部分保存时是UNKNOWN，先查原操作与官网，不能换号再次提交。

需要拆段时，用`pavo_script_create_storyboard_segment`新增片段，读真实默认场景/镜头，必要时用`pavo_script_create_storyboard_shot`补镜；把完整台词、动作及素材标签保存并回读后，才用`pavo_script_delete_storyboard_shot`删去已经迁移的旧镜。每一步使用刚回读的新整集指纹。单镜可编辑1至15秒，但段总时长应服从实时所选生成模型；不因文字很长就把段总时长填成几十秒。
