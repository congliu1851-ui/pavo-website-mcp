# 分镜编辑协议及验证边界

核对时间：2026-10-30。依据官网当前分镜页前端，不以猜测路径代替证据。

| 行为 | 官网合同 |
| --- | --- |
| 读取分镜 | `GET /api/v1/pixa/short-drama/episodes/{episode_id}/storyboard/detail` |
| 保存镜头及场景 | `PATCH /api/v1/pixa/short-drama/shots`，`shots:[{shot_id,content_rich,duration_sec}]`、可选`scenes:[{scene_id,content_rich}]` |
| 新增片段 | `POST /api/v1/pixa/short-drama/episodes/{episode_id}/segments`，仅传`display_order` |
| 新增镜头 | `POST /api/v1/pixa/short-drama/segments/{segment_id}/shots`，仅传`display_order` |
| 删除镜头 | `DELETE /api/v1/pixa/short-drama/shots/{shot_id}` |

保存函数将同段镜头的富文本与时长一起提交，检查`results`和`scene_results`中的失败，再重新读取完整分镜。编辑器时长校验只接受1至15的整数。未核到独立编辑镜头标题、片段概要或视频提示词的官网合同，因此工具不开放这些字段。

官网新增片段后会回读并打开新增对象；具体是否自带场景/默认镜头、编号及默认内容必须使用本次真实响应，不从测试夹具推断。没有发现原生移动镜头的前端合同；拆段使用新增、保存核验、最后删除原镜的显式步骤，工具不自动搬移或先删。

## 工具保护

- 整次操作沿已有账号认证快照、稳定操作号和项目锁执行，核项目/分集/镜头归属及只读、运行任务和最新指纹。
- 富文本素材标签必须完整且属于本项目的实际角色、场景或道具状态。允许明确替换引用，回读核每个已编辑镜头的自身标签，场景层另核汇总；官网初次生成时可能带入场景引用，编辑后不强加此继承关系，也不机械要求原引用恒不变。
- 保存后核正文和时长，并逐切核派生视频提示词的新正文、实际切点及段总时长，非空但陈旧的提示词仍拒绝。既有媒体URL/选择ID、模型、未改内容和其它字段受保护。
- 新增结构保留既有对象相对次序；受控删镜不删除场景最后一镜，整段迁移删除另按文末受控流程执行，不提供通用项目、资产或媒体删除。
- 请求可能已写入后出现部分失败、回读不符或网络异常时，保持UNKNOWN并占用该集写claim，禁止换号重投。必须核原回执和真实官网状态。
- 分镜写入前的项目、制作列表、详情及素材引用预检都是纯读取；这些读取遇到API错误（包括HTTP 567）时，明确记FAILED及“未提交写请求”，保留安全错误码且不取得新的写claim。提交后的同类回读错误仍记UNKNOWN；不能只因错误码相同而按未提交重试。此分类仅用于分镜编辑，不改变其它剧本工具。
- 官网无原子版本CAS，本机指纹只能降低竞态；编辑期间应避免网页同时修改同一分镜。已生成媒体是否仍符合新脚本需另作视觉核验，保存工具不替代该核验。

## 时长与费用

编辑器的单镜范围不是视频模型单段上限。2026-10-30账号只读模型列表：Agnes Video 2.5及Flash支持4至12秒，MiniMax H3支持4至15秒。每段总时长由该段镜头求和，实际生成前仍读取当前所选模型。

这些编辑工具不运行图片、视频、重生成或合成，不为验证而消耗生成额度。离线测试及只读联调的通过不能证明生产写入、生成质量或口型效果；生产编辑应使用用户已授权的实际优化文字并保存回读回执。

2026-10-30首批用户优化文本保存已真实回读确认：两镜新正文及3秒/8秒、11秒段时长、派生视频提示词全文及切点均匹配，媒体及其它字段保留。初版验证器误将生成时的场景继承强加给保存后的单镜引用，已修复；原UNKNOWN经精确匹配原写前SHA与当前结果，只读核实并保留原审计后确认成功，未重投官网写请求。此结果只验证本次实际文字保存，不外推结构创建/删镜或生成质量。

分镜保存的已核官网UI范围是当前单一片段。工具现拒绝跨片段批量保存，整集须逐段调用。一次跨9段的整集请求被官网067012明确拒绝，拒绝后快照SHA与写前完全一致，证明没有落地；旧Client未保留原响应正文，不能把该码猜解为时长错误。输入范围收紧按已核UI合同执行，不以另发测试写请求探测。

场景编辑字段是场景素材选择，不是自由环境文案字段。一次纯文字病床说明未替换原客厅绑定，而同批镜头新正文及时长已经保存，回读因此正确保持UNKNOWN。工具已在HTTP前将场景字段限制为一个完整的本项目scene标签；详细描述仍可完整写在镜头正文。缺少准确场景资产时先补原剧情地点的资料，不拿其它场景图冒充。此类部分保存不能标完整成功，也不能换号盲重投。

上述场景部分保存已由原写前指纹匹配的完整前态及实际结果逐字段核清：原操作保留UNKNOWN历史后归为已知部分失败FAILED，结果标partial_applied=true，未重放原请求。该确认没有发官网写请求，也没有把部分保存冒充成功；后续修复应使用正确场景标签与新明确输入。

业务错误诊断现保留HTTP状态、业务码及有限固定类别线索（如请求限流、任务繁忙、状态冲突、时长校验等）；从message/error_message提取类别，不保存或回显任意原消息、认证、URL或敏感正文。类别仅是关键词线索，不等于已确认根因；不因分类而自动重试。


## 2026-10-30制作分集与片段媒体扩展

官网另有GET `/api/v1/pixa/short-drama/projects/{project_id}/episodes/storyboard`制作列表。首次分镜可为`pending/shot_count=0/enterable=false/batch_generate_selectable=true`，此时详情不可进入，不能先GET detail再POST generate。MCP改用原生列表核归属及首次可生成性，已有可进入分镜仍核详情、运行任务与regenerate。正文编辑继续使用progress中的正文分集，不按标题映射；导出同时包含分镜时按同项目唯一episode_no记录两类ID，pending只记录原生可用性，不伪造空分镜详情。

关键帧与视频属于segment片段，一段多镜只有该段关键帧槽。需要逐镜独立图片/视频时先审剧情，再用已有新增片段/镜头、保存回读、最后删除已迁移旧镜的流程拆段。

| 用途 | 原生合同 |
| --- | --- |
| 短剧模型 | GET `/api/v1/pixa/model_options`，query `scene_code=segment_keyframe`或`segment_video` |
| 已上传关键帧关联 | POST `/api/v1/pixa/short-drama/segments/{id}/media/upload`，`media_type:image,role:segment_keyframe,url,thumbnail_url` |
| 已上传视频关联 | 同上，`media_type:video,role:segment_video,url,first_frame_url` |
| 媒体历史与状态 | GET `/api/v1/pixa/short-drama/segments/{id}/media`，query `role=segment_keyframe`或`segment_video`；响应items |
| 选择已有媒体 | PUT `/api/v1/pixa/short-drama/segments/{id}/media/{media_id}/select`，无请求体 |
| 单段视频 | POST `/api/v1/pixa/short-drama/segments/{id}/video/generate`，`model_code,resolution,style_id`或`custom_style_prompt,keyframe_production_mode:single_frame`，可选`upload_reference_image_url` |

绑定工具先核项目/制作集/片段归属及`_mcp_fingerprints.media`，保存历史后显式选择并回读对应`selected_keyframe_id/url`或`selected_video_id/url`。沿用稳定operation_id、账号/项目锁、未知提交claim，部分上传成功但选择或回读保护检查失败时保持UNKNOWN，不能换号重投。已有同URL唯一媒体直接复用，不重复上传。另一个槽、既有媒体URL、分镜文字/顺序/时长及正文标题受保护。官网无原子CAS，应避免网页并发编辑。

视频工具要求显式模型、分辨率、style和expected_ratio。ratio只核实际项目，不把未核的ratio字段发给官网；时长按本段全部镜头求和并核estimated_duration_ms及实时模型约束，图片输入模式也须实时支持。只支持已核single_frame合同，不提供猜测的prompt、首尾帧、音频开关或段设置参数。

查询从本片段segment_video历史精确匹配generation_task_id，保留task_status。已核前端运行态为running/generating/processing/waiting系列，原生结果事件使用success/failed。查询在success且有本任务产物时成功；原生完成后也可能以无task_status的持久化资源返回，此时须同时具有kind=media、media_id、media_type=video、role=segment_video、source=ai_generate及HTTPS产物，才以persisted_native_generated_video为完成依据，不补造task_status。只有URL、上传媒体或任务暂缺均不算完成。明确failed时可在授权范围内显式重试，运行超时不能代替失败。原pavo_get_task是画布接口，未复用为短剧任务查询。巡检间隔、单任务限制、重试次数与总产物上限由调用方按用户授权执行，工具不后台循环或自动扣费。项目有active_tasks时沿用全局写保护，暂不开放跨段并行生成。
